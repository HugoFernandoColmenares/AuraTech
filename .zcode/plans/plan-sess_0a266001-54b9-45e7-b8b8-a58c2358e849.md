# Plan: Sistema Dinámico de Mapeo de Excel (Custom Excel) + verificación de cascade delete

## Decisión de la primera parte: el cascade delete YA existe
`app-data-table` (usado por `sales-table`) ya implementa selección múltiple (checkboxes), toolbar "Delete selected", y emite `bulkActionClick = { action: 'bulkDelete', rows }`. `sales-report.component.ts` ya lo conecta: `handleBulkAction` → `confirmBulkDelete` → `confirmAndRemoveBatch` (AlertService.confirm + `salesApi.remove(id)` por fila) → `refreshAfterMutation` (invalida caché, refetch, `tableSelectionReset++`).

Per tu respuesta, esta entrega **no añade código a esta parte**: haré una verificación end-to-end del flujo existente y corregiré solo si encuentro un bug (p.ej. `selectionKey` compuesto `${base}::p${page}::i${index}` que ya evita colisiones entre páginas). No se crea nada nuevo aquí.

El resto del plan es el **servicio de subida/normalización de Excel reutilizable + modal de mapeo visual contra `ISaleRecordDto` + persistencia de plantillas globales**.

## Fase 4 — Servicio de dominio `CustomExcelMappingService`
**Archivo:** `src/app/core/services/Excel/custom-excel-mapping.service.ts` (`providedIn: 'root'`, SRP — orquesta parseo↔mapeo↔persistencia, sin tocar UI).

Responsabilidades (SRP, métodos pequeños):
- `loadTemplates(): Promise<void>` — carga plantillas vía API service → signal `templates`.
- `applyTemplate(rows, template): ISaleRecordDto[]` — dado el JSON normalizado + `propertiesMap`, mapea a `ISaleRecordDto` reutilizando `parseCurrency`/`parseInteger` de `core/auxiliar/excel-parse.utils.ts` y `lookupBrandCollection` para brand/collection (igual que `parseWalmartWfs`). Genera `id` GUID y `isLocal: true`.
- `previewRows(rows, template, limit = 5): ISaleRecordDto[]` — para la tabla de vista previa del modal.
- `saveTemplate(dto): Promise<void>` y `validatePropertiesMap(map): string[]` — valida sin duplicados de columna destino (`auditMonth`/`auditYear` opcionales excluidos del check de duplicados).

No duplica lógica de parsers existentes: **es una rama nueva** "custom" en `StoreType` (ver Fase 6), paralela a los parsers hardcodeados.

## Fase 5 — Modal de mapeo visual `CustomMappingModalComponent`
**Archivos nuevos:** `src/app/pages/sales-report/components/custom-mapping-modal/{*.ts,*.html,*.css}` (standalone, OnPush, imports `ReactiveFormsModule` + `DropdownModule` de PrimeNG).

Patrón existente a seguir: `store-selection-modal` (input/output + signal, sin DynamicDialog; el padre lo renderiza con `@if`). Clases globales Art Deco: `.modal-overlay/.modal-card/.modal-header/.btn/.btn-primary`.

Flujo guiado en pasos (signal `step = signal<1|2|3|4>(1)`):
1. **Upload**: drag-drop/`<input type="file" accept=".xlsx">` → `ExcelHandlerService.getSheetNames()`.
2. **Sheet select**: `p-dropdown` con los nombres de hoja + datos crudos via `getSheetDataWithNormalizedHeaders` (cabeceras ya dedupeadas).
3. **Mapping grid**: tabla 2 columnas (`ISaleRecordDto` property ↔ Excel column via `p-dropdown`). Definición de propiedades como `const` (DRY): `SALE_MAPPING_FIELDS = [{key:'orderId',label:'Order ID',required:true}, …]`. Cada dropdown alimenta un `FormGroup` reactivo. **Validación de duplicados en tiempo real**: una columna Excel no puede aparecer en 2 propiedades (excepto las opcionales no asignadas); el botón "Process" queda deshabilitado y se muestra badge de error si hay duplicado. Campos de metadata: `accountName` (input), `category` (Retail/Wholesale), `sheetName` (auto desde step 2), `dateFormat` (input opcional).
4. **Preview**: tabla de las primeras N filas ya mapeadas a `ISaleRecordDto` vía `CustomExcelMappingService.previewRows`.

Outputs: `confirm = output<{ records: ISaleRecordDto[]; template: IExcelMappingDto }>()`, `cancel = output<void>()`.
Checkbox "Guardar plantilla en base de datos" → al confirmar, guarda antes de emitir.

## Cómo se aplican SOLID/DRY/KISS
- **SRP**: parseo (ExcelHandlerService) ↔ orquestación (CustomExcelMappingService) ↔ persistencia (ExcelMappingsApiService) ↔ UI (modal) separados.
- **DRY**: `SALE_MAPPING_FIELDS` define propiedades una vez; reutiliza `parseCurrency`/`parseInteger`/`lookupBrandCollection`; extiende `BaseSupabaseApiService` y el patrón modal existente; registro centralizado en `SUPABASE_TABLES`.
- **KISS**: rama nueva `custom-excel` paralela, sin refactor de los 10 parsers hardcodeados; señales + `async/await` (sin RxJS para estado, igual que el resto del app).
- Angular 19: signals, `input()`/`output()`/`computed()`, standalone, OnPush, control flow `@if`/`@for`.

## Fuera de alcance (esta entrega)
- Mapeo visual para Inventory/Products/CreditCard (queda el servicio de parseo genérico listo; solo Sales funcional).
- Selección persistente entre páginas / contador total en el data-table (cascade delete ya funciona).
- i18n (la app no tiene framework de traducción; UI en inglés inline como el resto).
