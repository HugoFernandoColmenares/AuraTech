User Guide & Technical Overview

Welcome to AuraTech, a sales analytics demo. This guide explains how Excel uploads, browser session data, and Supabase persistence work together.

@switch (section.id) { @case ('dashboard') {

The Dashboard is your starting point. It summarizes the end-to-end workflow: open a report, upload Excel, review parsed rows, and export session data to Supabase.

Each report module (Sales, Products) follows the same coordinator pattern: filters and analytics at the top, detailed tables below, and toolbar actions for upload, export, and database sync.

} @case ('upload-workflow') {
  1. Prepare your Excel file. Use the generic sales template or Custom Excel mapping. Column headers must match the parser or the mapping you define.
  2. Navigate to the report module and switch to the Data or table view when available.
  3. Click Upload Data in the table toolbar (requires bulk-upload permission). Choose the file from your computer. For Sales you pick Generic or Custom Excel before parsing begins.
  4. Wait for parsing to finish. The global loader shows progress. Invalid or duplicate rows may be removed according to the same curation rules used during database export (especially in Sales).
  5. Review the table. Filter, search, and spot-check amounts, SKUs, and dates before sending anything to production.
  6. Check the data-source indicator (session vs database icon) to confirm how many rows are still only in your browser.
  7. Export to DB when you are satisfied. Session rows are bulk-upserted to Supabase. After success, the module refreshes paginated data and analytics from the server.

Uploading does not write to Supabase automatically. Closing the tab or clearing session data removes unpersisted rows unless you exported them first.

} @case ('custom-excel') {

Custom Excel is for sales spreadsheets that do not match the generic template. You map your own column headers to AuraTech sales fields in a four-step modal, preview the parsed rows, then load them into the browser session like any other upload.

  1. Open Sales Report and switch to the Data table view.
  2. Click Upload Data in the toolbar and choose your .xlsx or .xls file.
  3. Select Custom Excel in the store picker (🧩 icon) and confirm.
  4. Step 1 — File: verify the selected workbook, then click Continue with file in the modal footer.
  5. Step 2 — Sheet: pick the worksheet that contains your data. Use the search box in the dropdown if the workbook has many tabs, then click Load sheet.
  6. Step 3 — Mapping: enter the account name and category, optionally set a date format and audit period, then map each required sales field (Order ID, SKU, Qty, Total, Date, etc.) to the matching Excel column. Dropdowns are searchable to speed up wide spreadsheets. Optionally load a saved template or check Save this mapping template for next time.
  7. Step 4 — Preview: review the first mapped rows, then click Load N records to import into the session.
  8. Review and export: filter the table, confirm totals, then use Export to DB when you are ready to persist the session rows to Supabase.

Date filters in Sales Report use the audit period (audit month/year), not necessarily the order date shown in the table. Set audit month/year in the mapping step when your file has no dedicated audit columns.

} @case ('export-db') {

Export to DB uploads rows flagged as session/local data through the module API (bulk upsert). It is available in the table toolbar for users with bulk-upload permission.

  • The button stays disabled when there are zero session rows pending export.
  • Sales records are curated before upload (cancelled/refunded rows removed, Shopify summary deduped).
  • On success you will see a confirmation toast and the table reloads from Supabase.
  • On failure, verify Supabase environment variables locally or on Vercel.

Excel export and JSON export are separate actions: they download a file from your current view or full dataset without modifying the database.

} @case ('data-sources') {

The toolbar data-source indicator shows where the current dataset comes from:

  • Session / cache — rows parsed from Excel or created locally (isLocal). Pending Export to DB.
  • Database (Supabase) — rows already persisted and loaded via paginated API reads.
  • Mixed — both session and database rows are present (uncommon; export session rows first).

Read-only GET responses may be cached for the browser session to avoid redundant Supabase calls. Any successful write (Export to DB, CRUD) invalidates that cache for the affected report.

} @case ('sales-reporting') {

Import sales with the generic template or Custom Excel mapping, then explore Analytics and Data views.

For non-standard layouts, use Custom Excel to map columns manually and save reusable templates. See the Custom Excel Mapping (Sales) section above for the full walkthrough.

Filters support account, date range, month selection, and SKU search. Server-side analytics use Supabase RPC functions when the database is reachable.

} @case ('catalog') {

The Product Catalog stores SKU, style name, brand, type, and collection as plain text for the demo.

} @case ('management') {

Manage products manually or via Excel import. Brand, type, and collection are free-text fields. Session imports follow the same Export to DB pattern as report modules.
